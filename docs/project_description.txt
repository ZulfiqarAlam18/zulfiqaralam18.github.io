2. TECH STACK
-------------

- HTML5 — hand-written pages, semantic markup, schema.org microdata (itemscope / itemprop).
- CSS3 — purpose-based stylesheets in assets/css/ (see Section 3) built on CSS custom properties (design tokens in :root): colours, syntax-highlight colours, fonts, radius, easing. Monochrome dark theme: #0b0e13 background, off-white accent (--accent: #e6edf3) with grey secondary tones, and labels styled like grey code comments. The only colour outside the code window is --status: #22c55e, reserved for "live" / "available" signals (avatar dot, live badges, build tick). To re-theme, change --accent, --accent-2, --accent-soft, --accent-line and --status in :root. Typography uses an 8-step scale (--fs-xs 12px … --fs-3xl 32px) — every font-size uses one of these tokens, and nothing is smaller than 12px. Small grey text (--text-dim: #808d9b) is 5.3:1 on cards, passing WCAG AA. Section rhythm comes from --section-pad (64px desktop, 48px phones), giving about 130px between sections. Grid/Flexbox layouts, breakpoints at 1024 / 860 / 640 px, and a prefers-reduced-motion block that disables animation.
- Vanilla JavaScript — one shared script (assets/js/main.js), no frameworks, no bundler.
- Fonts — Google Fonts Inter (text) and JetBrains Mono (code-style labels, logo, tags), loaded with a <link> in each page head (not a CSS @import, which delays rendering).
- Icons — Font Awesome 6.5.1 from cdnjs on every page, loaded non-blocking (rel="preload" + onload, with a <noscript> fallback) so it never delays first paint.
- Markdown rendering — marked 12.0.2 (jsDelivr), used only by case-study.html.
- Forms — FormSubmit (formsubmit.co) delivers contact-form messages by email; the script posts to its /ajax/ endpoint. A hidden _honey field (FormSubmit's honeypot) filters spam bots.
- Analytics / SEO — Google Analytics 4 (gtag, ID G-4YV1D6R3HX), Google Search Console verification meta tag, JSON-LD, Open Graph, Twitter Cards, sitemap.xml, robots.txt.
- PWA metadata — manifest.json.
- Tooling — dependency-free scripts in scripts/: serve.js (local preview), check-links.js (link/image verification), make-images.js (regenerates web images and icons from the originals via headless Chrome) and create-blog-post.sh (new post from a template).
- Hosting — GitHub Pages. Push to main and the site updates.

There is no package.json, no dependencies to install and no build step. Only 3 animations run continuously (the avatar's status pulse and two blinking cursors); everything else plays once.

5. JAVASCRIPT BEHAVIOUR (`ASSETS/JS/MAIN.JS`)
---------------------------------------------

Shared by every page; every feature checks that its elements exist, so pages without them are unaffected.

- Resume config — RESUME_CONFIG at the top holds filename (assets/resume/Zulfiqar_Alam-Mobile_Application_Engineer.pdf) and downloadAs. Every [data-resume-link] gets its href from it; [data-resume-download] also gets the download name.
- Footer year — fills [data-year] with the current year.
- Mobile menu — toggles #mobileMenu, swaps the icon, sets aria-expanded, closes when a link is tapped.
- Navbar — adds .scrolled after 20 px of scroll.
- Active nav link — IntersectionObserver marks the link of the section in view.
- Scroll reveal — .reveal elements fade up; children of [data-stagger] fade up one after another. Section headings (.section-head[data-stagger]) use a masked word reveal: main.js wraps each title word in a clipping box, the // label slides in from the left, each word slides up from behind its box with an 80 ms stagger, then the rule beside the title draws left to right (CSS in motion.css; the whole sequence takes ~1.3 s and settles at 1.7 s). Skipped entirely under reduced motion. After the entrance the hooks are removed so hover effects behave normally.
- Count-up — [data-count] numbers count from 0 when revealed.
- Typed role — [data-typed] (JSON array of strings) types and deletes each phrase in a loop.
- Code editor typing — reads the highlighted code already in #codeTyping, empties it and types it back character by character (indentation is instant, short pause at line ends), line numbers appear as lines are reached, then #codeStatus lights up. Without JS the full code is shown.
- Scroll progress bar — a thin accent line at the top of every page fills as you scroll.
- Back to top — a button appears after scrolling most of a screen.
- Card spotlight — on devices with a mouse, cards get a soft glow that follows the cursor.
- Card filters — [data-filter-target] bars (projects page and blog page) show/hide cards by data-tags, update an optional counter (data-filter-count) and empty state (data-filter-empty), and replay a short entrance animation.
- Code copy buttons — every <pre> in a blog post gets a copy button.
- Contact form — posts FormData to FormSubmit's /ajax/ endpoint, shows a spinner, then a success or error toast.
- Copy buttons — [data-copy] copies via the Clipboard API (textarea fallback) and briefly shows "Copied".
- Toasts — showNotification(message, type) builds the toast with textContent (no HTML injection); styling lives in CSS.
- Reduced motion — with prefers-reduced-motion, typing, count-up and reveals are skipped and content shows immediately.

8. COMMON MAINTENANCE TASKS
---------------------------

Update profile content
- Treat user_context.txt as the source of truth. Profile text lives in index.html (hero, about, experience, skills, background, JSON-LD) and projects.html.
- The hero code window is plain HTML in #codeTyping: one <span class="line"> per line, with tk-key, tk-type, tk-str, tk-num, tk-fn, tk-com, tk-meta spans for colours. Edit it like normal HTML; the typing animation adapts.
- Typed role phrases are in the data-typed attribute on the hero.

Update the resume
1. Put the new PDF in assets/resume/.
2. Change RESUME_CONFIG.filename in assets/js/main.js (and optionally downloadAs).
3. Also replace the file name in the hrefs in index.html and projects.html, so links work before JS runs.

Add a project
1. Add a write-up to case-studies/<slug>.md (kebab-case) and add the slug + title to CASE_STUDIES in assets/js/case-study.js.
2. Copy an <article class="feature-card"> in projects.html; set data-tags (live / mobile / web / ai), the title-bar label, and the case-study.html?p=<slug> link. Keep the badge-live span only for Play Store apps.
3. To feature it on the home page, copy the same card into index.html. Add the case-study URL to sitemap.xml.
4. Update the "11 projects" count in the About stats and the "All 11 Projects" button.

Write a blog post
1. Run scripts/create-blog-post.sh "Post Title" "post-slug" "category" from any folder (Git Bash / WSL on Windows).
2. Fill in description meta tags and the body in blog/post-slug.html.
3. Add a .blog-card with matching data-tags to blog/index.html and the URL to sitemap.xml. Once posts span more than one category, remove hidden from the .blog-filters block.
4. Commit and push.

Deploy
- git add, git commit, git push origin main. GitHub Pages publishes within a minute or two.

Run locally
- Run node scripts/serve.js and open http://localhost:8080. Don't open files directly: case studies are fetched over HTTP and the 404 page uses root-relative paths.

Before pushing
- Run node scripts/check-links.js (exits with an error if any local link or image path is broken).
- After a deploy, a hard refresh (Ctrl + Shift + R) avoids mixing a cached old stylesheet with new HTML (GitHub Pages caches files for 10 minutes).

Replace the profile photos
- Put new originals in assets/images/profile/original/ (same names) and run node scripts/make-images.js.
